# Spotify - Azure End-to-End Data Engineering Project

This repository contains an end-to-end data engineering project that ingests Spotify data and demonstrates an Azure Data Factory (ADF) based pipeline for extraction, transformation, and loading (ETL). The project showcases advanced data engineering patterns including incremental ingestion strategies on Azure cloud infrastructure.

## Project overview

- Purpose: Demonstrate a complete data engineering workflow on Azure using ADF, including linked services, datasets, pipelines, and publish configuration.
- Source data: Example Spotify data (sample CSV/JSON files) stored under the `dataset/` directory.
- Orchestration: Azure Data Factory pipeline definitions are included under `pipeline/` and can be deployed using ADF publishing.
- Infrastructure artifacts: ADF factory JSON and linked service definitions are stored under `factory/` and `linkedService/`.

## Repository structure

- `dataset/` — sample data files used by the pipelines
- `factory/` — ADF factory artifacts (ARM/ADF JSON definitions)
- `linkedService/` — ADF linked services (connections to storage, etc.)
- `pipeline/` — ADF pipeline definitions
- `publish_config.json` — ADF publish configuration produced when publishing from the ADF UI

> Note: This branch (adf_publish) typically contains artifacts generated by the ADF "Publish" action. These artifacts are safe to commit for collaboration or deployment, but sensitive credentials should never be committed—use Azure Key Vault instead.

## Key Pipelines

### 1. Incremental Ingestion Pipeline
**Purpose:** Implements efficient incremental data loading with conditional logic to handle both initial full loads and ongoing delta ingestions.

**Architecture Overview:**
- **Lookup Activity**: Retrieves the last CDC (Change Data Capture) timestamp from a control table
- **Set Variable Activity**: Stores the current timestamp for comparison
- **AzureSQLtoLake Activity**: Copies only changed data from Azure SQL Database to Data Lake
- **If Condition Logic**: 
  - **True (Incremental Mode)**: Updates existing records in the target dataset
  - **False (Initial Load)**: Deletes and replaces entire temporary files

This approach minimizes data transfer and processing overhead by only ingesting records that have changed since the last run.

### 2. With Loop Incremental Ingestion Pipeline
**Purpose:** Enables batch processing of multiple data sources using a ForEach loop with incremental logic.

**Architecture Overview:**
- **ForEach Loop**: Iterates through an array of source table configurations
- **Activities within Loop**:
  - **Lookup Activity**: Queries source system for delta records
  - **AzureSQLtoLake Activity**: Stages the incremental data
  - **IfIncrementalData Activity**: Conditional logic to determine processing path
- **Web Activity (Alerts)**: Sends success/failure notifications via webhook after processing completes

This pipeline is ideal for enterprise scenarios where you need to process multiple Spotify data feeds (e.g., user data, streaming events, playlist metadata) concurrently while maintaining incremental ingestion patterns.

## How to use

1. Clone the repository:
   ```bash
   git clone https://github.com/ndarji0110/Spotify---Azure-End-to-End-Data-Engineering-Project.git
   cd Spotify---Azure-End-to-End-Data-Engineering-Project
   ```

2. Open the Azure Data Factory UI and import the ADF resources:
   - In ADF, go to Manage > Git Configuration to connect the repo (optional).
   - Use the "Import from ARM template" or deploy the factory artifacts in `factory/`, `pipeline/`, and `linkedService/` as needed.

3. Configure linked services:
   - Update linked service parameter values or configure them to use Azure Key Vault for secrets.
   - Ensure connections to Azure SQL Database, Data Lake, and other services are validated.

4. Set up control tables:
   - Create a control table in Azure SQL Database to track CDC timestamps for incremental pipelines.

5. Publish and run pipelines:
   - Once resources are deployed and linked services configured, publish in ADF and trigger the pipelines from the UI or via REST/PowerShell.

## Development notes

- Keep secrets out of the repo. Use Key Vault or pipeline parameters for credentials and connection strings.
- When you make changes in the ADF UI and publish, the generated JSON artifacts may change — commit them to this branch if you intend to track publish history.
- Test pipelines with sample datasets before running against production Spotify data.
- Monitor pipeline runs in the ADF Monitor hub for performance metrics and troubleshooting.

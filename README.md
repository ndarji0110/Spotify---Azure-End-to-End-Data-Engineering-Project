# Spotify - Azure End-to-End Data Engineering Project

This repository contains an end-to-end data engineering project that ingests Spotify data and demonstrates an Azure Data Factory (ADF) based pipeline for extraction, transformation, and loading (ETL) into a data lake. The content in this repo is organized to work with ADF publish artifacts and related Azure resources.

## Project overview

- Purpose: Demonstrate a complete data engineering workflow on Azure using ADF, including linked services, datasets, pipelines, and publish configuration.
- Source data: Example Spotify data (sample CSV/JSON files) stored under the `dataset/` directory.
- Orchestration: Azure Data Factory pipeline definitions are included under `pipeline/` and can be deployed using ADF publishing.
- Infrastructure artifacts: ADF factory JSON and linked service definitions are stored under `factory/` and `linkedService/`.

## Repository structure

- `dataset/` — sample data files used by the pipelines
- `factory/` — ADF factory artifacts (ARM/ADF JSON definitions)
- `linkedService/` — ADF linked services (connections to storage, etc.)
- `pipeline/` — ADF pipeline definitions
- `publish_config.json` — ADF publish configuration produced when publishing from the ADF UI

> Note: This branch (adf_publish) typically contains artifacts generated by the ADF "Publish" action. These artifacts are safe to commit for collaboration or deployment, but sensitive credentials should never be stored here — linked services should reference Key Vault or use parameterized secrets.

## How to use

1. Clone the repository:

   git clone https://github.com/ndarji0110/Spotify---Azure-End-to-End-Data-Engineering-Project.git
   cd Spotify---Azure-End-to-End-Data-Engineering-Project

2. Open the Azure Data Factory UI and import the ADF resources:
   - In ADF, go to Manage > Git Configuration to connect the repo (optional).
   - Use the "Import from ARM template" or deploy the factory artifacts in `factory/`, `pipeline/`, and `linkedService/` as needed.

3. Configure linked services:
   - Update linked service parameter values or configure them to use Azure Key Vault for secrets.

4. Publish and run pipelines:
   - Once resources are deployed and linked services configured, publish in ADF and trigger the pipelines from the UI or via REST/PowerShell.

## Development notes

- Keep secrets out of the repo. Use Key Vault or pipeline parameters for credentials and connection strings.
- When you make changes in the ADF UI and publish, the generated JSON artifacts may change — commit them to this branch if you intend to track publish history.
